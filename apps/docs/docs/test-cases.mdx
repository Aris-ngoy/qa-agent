## Where to create

In the desktop app: open an app → **Test Cases** → add a case. Or use the CLI:

```bash
yoqa cases list APP
yoqa cases create APP --title "Login" --tag smoke --flows-file ./flows.json
```

`--flows-file` takes a JSON array of steps:

```json
[
  { "flowId": "<reusable-flow-id>" },
  {
    "instructions": "Sign in with the test account",
    "expectedResult": "Home screen is visible"
  }
]
```

On `cases update`, `--flows-file` and `--tag` replace the whole list rather than appending.

## Structure

A test case has a **title**, one or more **flows**, and optional **tags**.

### Flows

- **`instructions`** — natural language description of what the agent should do.
- **`expectedResult`** — what to verify after the instructions. If omitted, the agent mainly checks that the flow completed without errors.
- **Reusable flows** — reference a shared flow by `flowId` instead of inlining instructions. Update the reusable flow once; every case that uses it picks up the change.

Each flow is either inline (`instructions` + `expectedResult`) **or** a reusable reference (`flowId`) — never both.

### Tags

Tags (e.g. `smoke`, `regression`) help filter cases in the UI and CLI (`yoqa cases list APP --tag smoke`). `--tag` is repeatable on both `cases list` (a case must carry every tag) and `cases create` / `cases update`. Naming a new tag creates it automatically.

## Configuration

Per-case options:

- **Appium capabilities** — override how the session starts for this case only. See [Appium capabilities](/guide/best-practices-appium-capabilities).
- **Saved scripts** — after a passing AI run, you can save a scripted replay for faster subsequent runs (script vs AI mode).
