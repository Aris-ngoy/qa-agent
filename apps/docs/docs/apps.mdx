An **app** is the top-level container for identifiers, shared context, cases, flows, tags, and builds.

## Identifiers

When you add an app (desktop UI or `yoqa apps`), provide:

| Field | Platform | Purpose |
| ----- | -------- | ------- |
| **name** | all | Display name (e.g. `MyApp`) |
| **prefix** | all | Short unique ID used by CLI catalog commands (`yoqa cases list APP`) |
| **bundle_id** | iOS | Bundle identifier (e.g. `com.example.myapp`) |
| **package_name** | Android | Package name (e.g. `com.example.myapp`) |
| **web_url** | Web | The page a Run on web opens first, `http` or `https` (e.g. `http://localhost:8081`) |
| **app_store_id** / **play_store_id** | optional | Store IDs for future store/TestFlight flows |

At least one platform identifier (bundle, package or Web URL) is needed to launch and target the app. A web-only App needs only a name and a Web URL:

```bash
yoqa apps create --name "My Site" --web-url https://app.example.com
yoqa apps update APP --web-url http://localhost:8081
```

See [Web](/docs/web).

## App context

**App context** is shared guidance injected into every run — credentials, screen names, global rules, and quirks. Write it once so each test case stays short.

Configure it in the app settings in the desktop UI, or via:

```bash
yoqa apps get APP --json
yoqa apps update APP --context "..."
```

`--context` overwrites rather than appends — read the current value with `yoqa apps get APP --json`
first, then send the old text plus your additions.

See [Writing good test cases](/guide/writing-test-cases) for what belongs in context vs instructions.
