The Manual Inspector is a desktop surface for **exploring** a connected device the way a QA engineer would, then turning what you did into a reusable script.

## Flow

<Steps>
  <Step title="Connect a device">
    Select an iOS or Android device/simulator so a device session is active.
  </Step>

  <Step title="Inspect">
    View the live screen. Select elements to target actions (tap, swipe, input, lifecycle).
  </Step>

  <Step title="Build a shell script">
    Actions append to a script (CLI-shaped commands) instead of requiring you to invent locators by hand.
  </Step>

  <Step title="Run or save">
    Execute the script against the session, export a report, or keep it for later regression.
  </Step>
</Steps>

## Live mirror and control

Inspector mirrors the device screen with a live-frame stream on iOS Simulator, real iOS, and
Android (multipart PNG frames, about one per second on Simulator — the screenshot-capture
ceiling). The badge on the mirror tells you which transport is active:

- **Live** — streaming frames straight from the runner.
- **Poll** — degraded fallback (screenshot every ~500 ms) when the stream breaks.

The live mirror never writes to disk; explicit screenshots and script reports still persist to
`~/.yoqa/runs/screenshots/`.

Toggle **Live control** above the mirror to drag directly on the device:

- **On** — pointer drags on the mirror map to touch events on the device (tap, drag, swipe). Element selection and the action menu are paused while you drag. If a gesture fails (for example the device connection dropped), a toast names the failure; a dropped control socket reconnects a few times before toggling off.
- **Off** — clicking an element opens the action menu so you can insert or run a scripted step.
- **Hold Control** (Select mode) — skip the accessibility-tree highlight and pick an exact `x,y` from the screenshot. A crosshair follows the cursor; click sets the point, then choose tap, double-tap, long-press, or input from the menu. Use this when hit-test cannot select a control. Coordinates are the same 0–1000 screenshot grid on iOS and Android.

Live control is exclusive with running scripts. The feed pauses while a script step is in flight so gestures do not interleave with the running script.

The live mirror never writes to disk. Explicit screenshots and script reports still persist to `~/.yoqa/runs/screenshots/`.

### Recovering a dropped session

Real iOS sessions can occasionally drop under load (for example, during long Inspector sessions with the live mirror running). When that happens, Inspector clears the feed and prompts you to reconnect manually — it does not attempt to reconnect on its own. A failed background tree refresh no longer treats a still-live session as ended.

- **Restart session** — the toolbar button above the mirror disconnects, reconnects, and remounts the live view. Use it when Inspector shows the Restart prompt, or any time the mirror looks stuck.
- **Connect** — pick the device again in the device selector to start a fresh session.

## Command bar

The command bar sits above the script and adds steps that don't need an element selection:

- **Swipe up / down / left / right** — appends a directional swipe on the current screen. Saving the inspector script as a catalog case now keeps swipe steps (screenshot `x,y` → `x2,y2`).
- **Scroll up / down / left / right** — appends a semantic scroll (`yoqa action scroll --direction …`). Prefer this over swipe when you just need content to move; use swipe for exact finger paths.
- **Back** — system back navigation (`yoqa action back`).
- **Home** — bare home-screen press (`yoqa action home`).
- **Dismiss keyboard** — hides the software keyboard (`yoqa action keyboard`).
- **Wait** — enter seconds and click **Add wait** to pause the script (useful between an app launch and an assertion).

Everything else — tap, drag, assert, input, and app control — lives on the **Selector Commands** menu that opens when you select an element on the screenshot.

## Selector Commands

Select an element on the live screenshot to open its action menu. Alongside the usual `tap`, `assertVisible`, and `inputText` actions, the menu exposes app control and deeplink helpers you can drop into the script:

- **activateApp** — bring an app to the foreground (launches it if needed). Prefilled with the selected app's iOS bundle ID or Android package; override to target a different app (for example, `com.apple.mobilenotes` to jump into Notes).
- **terminateApp** — kill the app with the given App ID.
- **restartApp** — terminate then activate the same App ID.
- **backgroundApp** — background the app for N seconds, then reopen it.
- **back** — system back navigation.
- **scroll up / down / left / right** — semantic scroll in place.
- **home** — bare home-screen press.
- **dismiss keyboard** / **press enter** — hide the keyboard or press return.
- **drag up / down / left / right** — slow press-move from the selected point (for sliders, handles, drag-and-drop).
- **openUrl** — open a URL through the OS. Works for custom schemes (`myapp://path`) and `https://` universal links.
- **acceptAlert** / **dismissAlert** — respond to the next system alert (permissions, App Store prompts, "Open in MyApp?" deeplink confirmations, etc.).
- **screenshot** — capture the current screen. Use **Insert & Run** to save an evidence PNG mid-flow (for example, right after a deeplink lands).
- **screenshot (path)** — same as above, but prompts for a destination path (for example, `/tmp/yoqa-screenshot.png`) so multiple captures don't overwrite each other.

System steps (`back`, `scroll`, `home`, keyboard) replay against the device but are skipped — with a warning — when saving as a catalog case, which today only converts tap / type / wait / swipe / drag / app-lifecycle / alert / assert.

Prompts for App ID, URL, and screenshot path prefill from the current selection or last-used value, so scripting a cross-app hop is a few clicks per step.

### Example: test a deeplink from Notes (iOS)

<Steps>
  <Step title="Open Notes">
    Add **activateApp** with `com.apple.mobilenotes` to jump into Apple Notes.
  </Step>
  <Step title="Trigger the deeplink">
    Add **openUrl** with `myapp://path` — or select the pasted link in Notes and tap it.
  </Step>
  <Step title="Handle any system alert">
    Add **acceptAlert** so the "Open in MyApp?" prompt resolves automatically on replay.
  </Step>
  <Step title="Return to the app">
    Add **activateApp** with your app's ID so the script ends in a known state.
  </Step>
</Steps>

## When to use it

- Learn screen structure before writing natural-language cases.
- Reproduce a bug with an exact sequence of gestures.
- Script cross-app or deeplink flows (Notes → universal link → your app) that are hard to describe in natural language.
- Produce a **saved script** after you understand the happy path (complementary to AI agent runs).

For autonomous NL cases, use [Test Cases](/docs/test-cases) + Runs. For agent-driven debugging from the terminal, use [CLI for agents](/guide/cli-for-agents).
