The Manual Inspector is a desktop surface for **exploring** a connected device the way a QA engineer would, then turning what you did into a reusable script.

## Flow

<Steps>
  <Step title="Connect a device">
    Select an iOS or Android device/simulator so an Appium session is active.
  </Step>

  <Step title="Inspect">
    View the live screen. Select elements to target actions (tap, swipe, input, lifecycle).
  </Step>

  <Step title="Build a shell script">
    Actions append to a script (CLI-shaped commands) instead of requiring you to invent locators by hand.
  </Step>

  <Step title="Run or save">
    Execute the script against the session, export a report, or keep it for later regression.
  </Step>
</Steps>

## Picking elements

The Inspector caches the current accessibility tree so hover and click hit-tests run locally. You get an instant highlight without waiting for a fresh page source per click.

- **Hover preview.** With Live control off, moving the cursor over the screen draws a dashed outline around the element under the pointer.
- **Click to select.** Clicking picks the smallest labeled control containing the point. When several nodes share the same label (for example, a `StaticText` inside a `Button` both labeled "Continue"), the Inspector selects the largest one so the highlight covers the full control instead of a nested leaf.
- **Refresh tree.** Use the toolbar **Refresh tree** button to warm the cache manually. The tree also refreshes automatically after Insert & Run or when Live control turns off.
- **Live mirror.** Under Stream, a tree refresh briefly pauses MJPEG and then resumes. The stream stays continuous the rest of the time.

## Change Selector

Every selection has a **preferred locator** — `id` when the element has one, otherwise `label`. The chosen locator drives the suggested action chips (`tap (id)`, `tap (label)`, `tap (x,y)`) and shows as a caption under the highlight.

Open the element action menu and choose **Change Selector** to cycle through alternatives without moving the cursor:

1. If the element has both an `id` and a `label`, the first press flips the preference from `id` to `label`.
2. The next press advances to the next overlapping candidate under the click point, from leaf to parent.
3. Cycling wraps back to the first candidate.

Use Change Selector when the initial highlight targets the wrong layer — for example, when you want the surrounding card instead of the button inside it, or when a locator by `id` is too brittle and you'd rather target by visible `label`.

### Example: switching from id to label

Say you click a "Continue" button that exposes both `id="continue_btn"` and `label="Continue"`. The Inspector selects the button with `id` preferred:

```text
id: continue_btn
```

Press **Change Selector** once to prefer the label instead:

```text
label: Continue
```

The suggested chip list re-orders to put `tap (label)` first, so the next Insert writes the action with `--label 'Continue'`.

## Command bar

The command bar sits above the script and adds steps that don't need an element selection. It has two controls:

- **Swipe up / down / left / right** — appends a directional swipe on the current screen.
- **Wait** — enter seconds and click **Add wait** to pause the script (useful between an app launch and an assertion).

Everything else — tap, assert, input, and app control — lives on the **Selector Commands** menu that opens when you select an element on the screenshot.

## Selector Commands

Select an element on the live screenshot to open its action menu. Alongside the usual `tap`, `assertVisible`, and `inputText` actions, the menu exposes app control and deeplink helpers you can drop into the script:

- **activateApp** — bring an app to the foreground (launches it if needed). Prefilled with the selected app's iOS bundle ID or Android package; override to target a different app (for example, `com.apple.mobilenotes` to jump into Notes).
- **terminateApp** — kill the app with the given App ID.
- **restartApp** — terminate then activate the same App ID.
- **openUrl** — open a URL through the OS. Works for custom schemes (`myapp://path`) and `https://` universal links.
- **acceptAlert** / **dismissAlert** — respond to the next system alert (permissions, App Store prompts, "Open in MyApp?" deeplink confirmations, etc.).
- **screenshot** — capture the current screen. Use **Insert & Run** to save an evidence PNG mid-flow (for example, right after a deeplink lands).
- **screenshot (path)** — same as above, but prompts for a destination path (for example, `/tmp/yoqa-screenshot.png`) so multiple captures don't overwrite each other.

Prompts for App ID, URL, and screenshot path prefill from the current selection or last-used value, so scripting a cross-app hop is a few clicks per step.

### Example: test a deeplink from Notes (iOS)

<Steps>
  <Step title="Open Notes">
    Add **activateApp** with `com.apple.mobilenotes` to jump into Apple Notes.
  </Step>
  <Step title="Trigger the deeplink">
    Add **openUrl** with `myapp://path` — or select the pasted link in Notes and tap it.
  </Step>
  <Step title="Handle any system alert">
    Add **acceptAlert** so the "Open in MyApp?" prompt resolves automatically on replay.
  </Step>
  <Step title="Return to the app">
    Add **activateApp** with your app's ID so the script ends in a known state.
  </Step>
</Steps>

## When to use it

- Learn screen structure before writing natural-language cases.
- Reproduce a bug with an exact sequence of gestures.
- Script cross-app or deeplink flows (Notes → universal link → your app) that are hard to describe in natural language.
- Produce a **saved script** after you understand the happy path (complementary to AI agent runs).

For autonomous NL cases, use [Test Cases](/docs/test-cases) + Runs. For agent-driven debugging from the terminal, use [CLI for agents](/guide/cli-for-agents).
